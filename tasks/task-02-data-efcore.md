# Task 02 — Data, EF Core, migrations, seed

**Session 1 · depends on: 01**

## Goal

Every table exists, created by a migration, filled by a seed that produces identical data every time
it runs.

## Stack for this task

EF Core 9+ with the SQL Server provider · `dotnet-ef` CLI · Bogus or a hand-written generator with a
fixed seed

## What to build

Entities and a `QuoteDeskDbContext`, configured with `IEntityTypeConfiguration<T>` classes rather
than a giant `OnModelCreating`:

```
Customers     (Id, Name, EmailDomain, WhatsAppNumber, Tier, CreditDays, GstIn, DefaultShipTo)
CatalogItems  (Id, Sku, Name, Category, Uom, ListPrice, CostPrice, Attributes)
StockLevels   (Sku, OnHand, LeadTimeDays, ReorderLevel)
PriceRules    (Id, Scope, Target, MinQty, DiscountPct)
OrderHistory  (Id, CustomerId, Sku, Qty, UnitPrice, OrderedAt)
Enquiries     (Id, Channel, SenderId, RawBody, ReceivedAt, CustomerId, Status)
Quotes        (Id, EnquiryId, Number, Status, Subtotal, Tax, Total, CreatedAt, ApprovedBy, ApprovedAt, SentAt)
QuoteLines    (Id, QuoteId, Sku, Qty, UnitPrice, DiscountPct, LineTotal, Note)
```

- `decimal(18,2)` explicitly configured for every money column — EF Core will warn otherwise
- An initial migration, generated by the CLI and committed
- A deterministic seeder using a **fixed random seed**, callable from a CLI flag, idempotent
- Repository interfaces returning plain records, not entities. Entities never leave this project.

The seed must include these deliberate cases, because everything downstream tests against them:

- two near-identical SKUs (`BRG-6203-2RS` and `BRG-6203-ZZ`)
- a customer with three prior purchases of the 2RS variant
- a catalogue item with two variants distinguished only by an attribute ("6mm" / "8mm")
- an item with 12 units on hand where a typical ask is 40
- a customer whose requested discount would breach the margin floor
- an enquiry from a sender in no customer record

## Acceptance criteria

- [ ] `dotnet ef migrations add InitialCreate` was used — the migration is not hand-written
- [ ] `dotnet ef database update` produces every table from scratch
- [ ] Running the seed twice produces byte-identical data
- [ ] Every one of the six deliberate cases is present and individually queryable
- [ ] All money columns are `decimal(18,2)`; no EF truncation warning appears
- [ ] Repository integration tests pass against the containerised database
- [ ] No entity type appears in any signature outside `QuoteDesk.Data`

## Out of scope

Pricing logic, agents, the API surface beyond what tests need.
